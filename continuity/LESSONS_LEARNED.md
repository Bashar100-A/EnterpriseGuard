# EnterpriseGuard ADIE — Lessons Learned

This file records mistakes, their root causes, and the preventive rules
that were introduced to avoid repeating them.

**Governed by:** continuity/RULES.md  
**Updated:** 2026-09-02

---

## 1. Qwen Document Pollution

**Mistake:** Qwen generated sensitive Markdown files that contained
stray command text and corrupted content.

**Lesson:** Sensitive foundational documents are written and saved
manually by the owner. They are never generated by Qwen.

---

## 2. Compound Orders

**Mistake:** Large orders that mixed creation, validation, baselining,
and documentation caused failures and confusion.

**Lesson:** One order must contain exactly one responsibility.

---

## 3. Missing Raw Evidence

**Mistake:** Some reports claimed success without showing raw output,
exit codes, or logs.

**Lesson:** No report is accepted without raw `stdout`, `stderr`, and
exit codes.

---

## 4. Duplicate DC Identifiers

**Mistake:** The same DC number was reused for different decisions,
causing governance conflicts.

**Lesson:** The next DC identifier is calculated dynamically from the
log, and duplicates are marked `SUPERSEDED-N`.

---

## 5. Temporary File Pollution

**Mistake:** Stray `.tmp` files appeared in `tools/` after interrupted
writes.

**Lesson:** All writes must use atomic patterns (`tempfile.mkstemp` +
`os.replace`) and temporary files must be cleaned up on failure.

---

## 6. Root Check Failures from Qwen

**Mistake:** Qwen repeatedly failed repository root checks even when
the files existed locally, due to path or environment mismatch.

**Lesson:** Critical verification commands are executed directly by the
owner in the local terminal, not through Qwen, when repeated failures
occur.

---

## 7. Incorrect DC Jump

**Mistake:** Attempted to register DC-049 when the next dynamic
identifier was DC-048.

**Lesson:** Always calculate the next DC number from the actual log
tail before appending. Never assume the next number.

---

## 8. Integrity Baseline Drift

**Mistake:** Dynamic files like `activity_log.json` caused repeated
`Integrity Baseline - modified` failures.

**Lesson:** Dynamic files are explicitly excluded from integrity
monitoring, while governance-critical files like `DECISIONS_LOG.md`
remain protected.

---

## 9. `identity_key` Stored Inside Chain Rings

**Mistake:** Early `innocence_chain` design stored `identity_key`
inside each ring, weakening verification.

**Lesson:** The identity key is read from the canonical
`hardware_identity.json` during verification, not stored inside the
chain artifacts.

---

## 10. Unreliable Automated Verification

**Mistake:** Relying on Qwen to run local tests caused repeated false
failures and wasted cycles.

**Lesson:** Unit tests are run locally by the owner when automation
fails, and raw output is posted for verification.
