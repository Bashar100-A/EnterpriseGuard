### Current Compatibility Policy

Root compatibility surfaces are not to be deleted merely because equivalent
`src` implementations exist.

Removal or deprecation requires:

1. consumer inventory,
2. migration evidence,
3. focused validation,
4. explicit owner approval,
5. and a separate recorded governance decision.

### External Proof Layer

ADIE v2.0.0 also has an independently verifiable validation layer consisting
of adversarial tests, Ed25519-signed reports, verification tooling, and
GitHub Actions CI.

The latest reported proof set includes:

* 148 adversarial tests,
* deterministic execution with `seed=42`,
* Ed25519 report signing,
* third-party verification using the public key,
* MITRE ATT&CK threat-model mapping,
* automated GitHub Actions validation.

The external proof layer and the core EnterpriseGuard/ADIE runtime architecture
must remain conceptually distinct: the proof artifacts demonstrate integrity
and validation; they do not replace the canonical runtime decision-control
architecture.

## Rules

* These files are written and updated manually by the owner.
* They are never generated by Qwen.
* They summarize and reference, not duplicate full content.
* Dynamic files such as `CURRENT_STATE.md` are excluded from integrity monitoring.
* `RULES.md` is the backbone and must be read first.
* Current-state summaries must not override `RULES.md`, recorded governance decisions, or raw verification evidence.
